- finding 1: the codex wire surface binds provider events through dd strict mode over the strict-decoded tree and emits request bodies via dd.Unbind + json.Marshal. two substrate facts cost real debugging time and are not obvious from the dd docs: dd's forgiving coercion path does not handle json.Number, so strict mode is the only binding posture that works on a strict-decoded tree — a second forgiving decode is both broken and lossy (float64); and json.Decoder.InputOffset after reading a key token sits on the separating comma/colon, not on the value, so wire.go's span capture must skip a run of separators before cutting an opaque byte span. the byte guarantees are two-tier and the distinction is load-bearing: saved continuation items are the provider's verbatim bytes (opaqueSpans cuts them from the SSE line), while outgoing requests re-serialize those items as strict trees — string values exact by code point, numbers exact by lexeme (verified beyond float64's exact range), escape spellings and key order normalized. do not 'fix' the outgoing path to claim whole-wire byte identity, and do not re-encode saved items.
- finding 1 follow-up: the output span walker had silently treated response.output {} as empty and dropped null array elements, so a completed streamed function call plus output {} or [null] produced a successful executable round. walkOutputArray now rejects non-array/non-null output and null/non-object elements with a protocol error, never repositioning elements; omitted, null, and [] output still preserve completed streamed items. fixtures: malformed shapes at parser level, empty/null positive coverage, and shared-loop cases asserting zero tool executions from the malformed round. mergeFinalItem compares backfilled fields by exact json.Number lexeme so adjacent large integers cannot compare equal and conceal a changed finalized field; an identical backfill returns the finalized bytes untouched.
- finding 2: UnmarshalDd binds the envelope's named fields (format, v, identity, bindings) through dd strict mode into private bind-only wire DTOs that carry the +nullable/+extra tolerance, then copies recognized fields into the shared RoundIdentity/CallBinding types, which keep their existing mappings and marshaling byte-identical. v binds as int through a narrowly scoped converter; opaque items are extracted first, object-validated, and re-encoded as supplied. unknown named keys are discarded on re-emission while unknown keys inside opaque items survive; float64-rounded values from forgiving intake are preserved rounded, never repaired.
- finding 2 follow-up: float64(math.MaxInt) rounds up to 2^63, so the old range check accepted an out-of-range float and int() wrapped it to MinInt64. the converter now checks the exactly representable half-open range [-2^(intBits-1), 2^(intBits-1)) derived from bits.UintSize, before conversion, on both boundaries. decoder-path fact: the forgiving json.Unmarshal path produces float64 for every number, including -2^63, which is exactly representable; the boundary tests exercise the true edges through that path via math.Nextafter — 2^63 rejected, the representable value just below it accepted, -2^63 accepted, and the value just below -2^63 rejected.
